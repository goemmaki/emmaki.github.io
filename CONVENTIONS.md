# Astro conventions

- Use design tokens from `docs/design-system/` and `globals.css` only. Do not introduce raw color, spacing, type, timing, or motion values.
- Render static markup in `.astro` files. Put behavior in vanilla TypeScript `<script>`s; the site is React-free and has no framework islands. Shared `src/lib` TypeScript modules are fine when they do not import React.
- For small menus and tooltips, keep static controls in `.astro` files and use native popovers plus small TypeScript keyboard/focus handlers. Match the reference widget's roles, names, states, dismissal and timing before replacing it.
- The first paint must already look like the settled page. Do not build visible DOM, insert text, or start textures in deferred scripts when HTML, CSS, or a tiny inline script immediately after the element can produce it.
- Preserve algorithms and timings when porting behavior. Honor reduced motion.
- Keep shared code in `src/`; avoid duplicate authorities.
- Native widget ports use Astro markup and small vanilla scripts; retain the source widget's keyboard, focus, animation, and find-in-page behavior before deleting its island.
- Run package commands from the repository root with `pnpm ...`.
- Compare changes with `node scripts/parity.mjs`. It captures both sites for each route, theme, and viewport, records metadata, selected element geometry/styles, errors, and JavaScript bytes, and compares full-page pixels. A pass means the recorded nonvolatile metadata, geometry, errors, and screenshot pixels match within the 0.5% raster budget; JS byte totals are informational because the bundles differ by design. On mobile only, document height may differ by up to the previously observed 6 px and is reported as an expected delta. The script masks only the volatile selectors declared at its top. Chromium uses sRGB output and stable font raster flags. Capture fixes `Math.random` before app scripts, waits for fonts, warms scroll-linked content, and allows 2.5 seconds for the initial animation state; it leaves page animations running, while fixing only the case-frame's animated gradient position in the listed capture CSS. Set `SELF_REPEATS=1` to capture each site a second time and record per-build raster noise. Dev servers can report HMR/toolbar errors, so use `REF=http://127.0.0.1:3006 NEW=http://127.0.0.1:3007` to compare production exports against the static export of `e504a4bd` served on port 3006 and the root `dist/` served on port 3007. Recreate the reference with `git worktree add <dir> e504a4bd`, `pnpm install`, `pnpm build`, then serve that worktree's `out/`. `INJECT_CSS` applies a deliberate style change to Astro only for hostile calibration checks. Use `FRAMES=1 BROWSER=chromium` for an acknowledged CDP screencast and per-frame changed-pixel table.
- Calibration evidence (2026-11-01): Firefox production comparison passed all 12 Home, Brands, and article cases (dark/light, 1440×900/390×844). A 1 px `main` translation and an explicit red foreground/background injection both failed as expected. Hue rotation alone was not a strong color probe on the mostly monochrome Brands capture; use a change that visibly affects a substantial region.
- Run checks through `run-check -- <command>` and judge the final `run-check: PASS|FAIL` line.
