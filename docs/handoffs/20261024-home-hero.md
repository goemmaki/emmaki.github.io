# Session handoff: home hero and site shell

## Owner goals and decisions

Goal: a Swiss-style, poster-like home hero for the emmaki Fiverr portfolio site, built to the site's design system (`docs/design-system/`, especially `DESIGN.md` and `DESIGN-HANDOFF.md`). Reference: the owner's "EYES WILL / FIRST GO HERE. / AND THEN HERE. | small text" poster, which is three tiers on one left axis.

Approved on 2026-10-24 (variant "F" in the lab):

- A **rectangle** whose height is set by a rotated "Hello!" (reads bottom to top), running from the cap height of "ANTI-SLOP" to the baseline of "HELP YOU?".
- Tier 1, "ANTI-SLOP / OPS HERE.", is Geist 600 capitals, -0.03em tracking, filling the text column exactly.
- Tier 2, "HOW CAN I / HELP YOU?", is two lines and takes 35% of the column.
- The H1, "I'm a B2B copywriter, AI content strategist, automation consultant, and *vituperative* Luddite.", sits beside the question, fitted to the same block so both end on one baseline. It is sentence case, Geist 500, white. Below 16px it drops under the rectangle at 20px.
- No rule between the question and the H1 (the owner disliked it). No yellow full stop (also disliked).
- Monochrome headline: "ANTI-SLOP" is in the headline colour, not yellow. The wordmark is white in dark mode.
- Sparkles on "vituperative" are brand yellow in dark mode and amber-orange (`#E07B00`, `#E86A00`, ≥3:1 on white) in light mode. Never brown, never green ("slop colour").
- The header hides on scroll down, returns on scroll up or keyboard focus, and is translucent with blur. The owner asked whether this fits the design; the agreed answer is yes, provided it stays restrained (70% canvas, light blur, 1px rule once scrolled).
- The menu has no numbers.
- The shell steps from 1200px to 1400px at 1600px and up. On big screens the hero centres vertically and is capped by viewport height. Empty space is fine; the owner plans a side-scroll or kinetic-type section straight after the hero.
- Copy is the owner's. Don't change or add words.

## Watch-outs and gotchas

- **Never merge to `main`.** GitHub Pages (legacy build) publishes `main` from its root; it holds only a README. Merging the Next.js source there would publish raw source. A deploy step comes first.
- `gh` is signed in as `slashrepeat`, which is not a collaborator on `goemmaki/emmaki.github.io`, so it can't open PRs. Pushes work over the `github-goemmaki` SSH remote. `design/foundation` has been updated by fast-forward pushes.
- `text-box: trim-both cap alphabetic` does the exact alignment. It works in Chrome; Firefox lacks it, so alignment is a few px off there.
- The hero CSS constants are measured. Re-measure if the copy, weights, tracking or the question's share (`--r`) change.
- On phones in landscape (about 844×390) the stacked H1 runs past the first screen. This is known and has been left as is.
- TypeScript type-checks every `.tsx` in the tree, including ignored scratch folders. Don't leave `.tsx` copies there, because they break `pnpm build`.
- `~/fiverr-portfolio` (the primary checkout, on `design/foundation`) is behind origin and has the owner's uncommitted files. Don't edit it; the owner pulls it themselves.
- Owner rule in `AGENTS.md`: if a change is rejected, stop, revert and ask.
