## Watch-outs and gotchas

- **Never merge to `main`**: GitHub Pages publishes it raw. "Push, merge" means fast-forward `design/foundation` (memory `emmaki-merge-target`).
- **Copy is the owner's.** Post text, CTA labels and AI questions stay obvious placeholders until the owner writes them.
- **Base UI menus:** modal by default, which locks scrolling. Keep `modal={false}` on `Menu.Root` in `post-tools.tsx`.
- **TOC tied to heading IDs:** the TOC throws if an entry's heading id is missing. IDs come from `headingId()` in `posts.ts`, so renaming a section renames its anchor.
- **Notch maths:** notch pitch × 6 must equal the TOC list's pitch (36px). Change the list's type or gap and the rail must change too.
- **Static export:** `output: "export"` with `dynamicParams = false`, so every post must appear in `generateStaticParams` (it maps `posts`).
- **Grafit is a reference only.** Never copy its code, text or assets.
- **Dev server: `localhost:3001` stopped reaching it (2026-10-25, unexplained).** The owner restarted `pnpm dev -p 3001` from Antigravity's terminal after Claude killed the previous server (PIDs 154298/154299). After that, `http://localhost:3001` showed a blank white page in the owner's browser and Antigravity's preview, and no `GET` line reached the server log. `http://192.168.20.5:3001` (the "Network" URL) works. Pages render without console errors in Chrome on eliteg6, so the fault is between the owner's machine and the server (most likely Antigravity's port forward), not in the site. Not yet diagnosed: check Antigravity's Ports panel. A `curl` on eliteg6 or a Chrome tab there proves nothing about the owner's view; only a `GET` line in the server log does. Over `192.168.20.5`, Next blocked its dev scripts as cross-origin (so the header and footer didn't work), until `allowedDevOrigins` in `next.config.ts` and a dev-server restart.
