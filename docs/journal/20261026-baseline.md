# Accessibility and browser baseline, 2026-10-26 (evening)

Measured at `06b3cb8f`, from a static export built at 03:10 on 2026-10-26 with the dev-only cover photo. This is a baseline for later comparison, not a WCAG 2.2 AA conformance claim.

## How it was run, and what went wrong

- **Codex (`gpt-6.1-sol`, high effort)** ran axe 4.14, keyboard, structure, motion, Firefox and resilience checks in Firefox 151 through Playwright 1.61. It covered 8 routes × light/dark × desktop 1440×900 and phone 390×844.
- **Claude ran Lighthouse** (desktop and mobile presets, dark theme by default) outside the sandbox, because Codex's sandbox blocked Chrome.
- **It took three attempts:**
  - Attempt 1: the sandbox blocked sockets, so there was no server, browser or build.
  - Attempt 2: the build still failed inside the sandbox, and Codex stopped to ask instead of measuring.
  - Attempt 3: measured a build Claude made outside the sandbox.
  - The first attempt also kept running alongside the second, because Claude's wait check watched the wrong process. Both were briefing and tooling errors by Claude.
- **Not tested:**
  - Safari/WebKit, which needs host libraries that require sudo (now a TODO)
  - a real screen reader
  - real devices
  - Chromium's animated cover, measured through the scroll (the earlier Chromium pixel measurements are in the 2026-10-26 transcript)

## Results

| Check | Result |
|---|---|
| Lighthouse accessibility | 96 on most pages; 100 on post mobile and hero-lab mobile. The only flag is the footer © line (3.59:1 against an assumed white). Rendered pixels show 5.1:1 / 5.9:1 on the black bar: a tool false positive, because the black sits on a separate layer behind the text. |
| Lighthouse best practices | 100 on every page |
| Lighthouse SEO | 100; `/hero-lab` 60 (deliberately noindex) |
| Lighthouse performance | desktop 97–98; mobile (simulated throttling) 75–84, LCP 4.5–7.0 s |
| axe (48 Firefox runs) | fails: hero-lab strip not keyboard-scrollable, hero-lab label contrast, cover contrast; best-practice: empty stub pages without an h1, the local test server's plain 404 |
| **Cover contrast in Firefox** | **fail.** Firefox has no `animation-timeline`, so it gets the static fallback, where the fade washes out the light-mode title: 1.89:1 desktop, 2.52:1 phone (needs 3:1). Header icons drop to 1.14:1 at 80svh in light mode and 1.90:1 at 30svh in dark desktop. |
| Focus visibility | the post menus pass (the 2026-10-26 fix holds). Cover focus rings in light mode measure 1.78–2.43:1 against the photo (1.4.11). |
| Keyboard | skip link, theme toggle, header menu (focus trap, Escape and return), tool menus and TOC all work. The hero-lab strip is unreachable (2.1.1). |
| Structure (screen-reader proxy, not a real screen reader) | landmarks and heading outline sound; the card title is hidden as intended; five decorative sparkle SVGs are exposed as unnamed images |
| Reduced motion | pass: sparkles hidden, footer drift stopped, nothing missing |
| Endless motion (2.2.2) | sparkles and footer drift run indefinitely with no site control; only the OS reduced-motion setting stops them. Needs a human judgement. |
| Broken cover image (Firefox) | no crash; a blank shaded cover. In Chromium the crash is known from the owner's 2026-10-26 report. |
| Standards basics | `lang` set, no duplicate ids, no missing alt, no nested interactive elements. Every page shares the home title/description; there is no custom 404 page yet. |
